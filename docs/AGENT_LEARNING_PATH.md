# Agent 学习与研究路线整理

- 整理日期：2026-10-04
- 来源：[Agent方向推荐](https://chatgpt.com/c/6ac26ee4-0680-83ee-8699-5bac8af4094c)
- 用途：研究生学习规划、Aier 项目定位、项目集与研究实验设计。

本文整理原对话中的建议，并结合 Aier 当前代码给出落地顺序。原对话提到的论文、年份、行业趋势和星级排序未在本次整理中独立核验，因此不作为学术证据；正式选题时需要另行查阅原论文与公开实验。下述方向是学习建议，未来能力不代表项目已经实现。

## 1. 总体目标与主线

目标是从零构建 Agent，理解执行循环、工具调用与上下文管理，逐步形成自己的轻量框架，再用应用与可复现实验支持科研和求职。

主线：**Agent Systems / Agent Infrastructure**。

重点能力：**Tool Use + Memory + Evaluation + Long-horizon Agent**。

可进一步聚焦的研究主题：**可靠的长期任务 Agent 系统**。这里的“长期”指需要多步执行、持续维护状态和处理失败的任务，不只是延长聊天历史。

```text
实际任务
  → 单 Agent 与工具调用
  → 自写执行循环与轻量框架
  → 运行轨迹与任务评测
  → 记忆、规划与失败恢复实验
  → 更复杂的应用与 Agent Learning
```

这是递进关系，不要求先完成一套大框架才能做应用或评测。

## 2. 各方向的角色

| 方向 | 在学习路线中的角色 | 适合研究的问题 |
| --- | --- | --- |
| Runtime / Infrastructure | 工程主线 | 如何管理上下文、工具执行、状态与终止条件 |
| Tool Use | 早期重点 | 如何选择工具、生成正确参数、处理失败与组合多个工具 |
| Evaluation / Reliability | 尽早建立的验证体系 | 任务是否完成、错在哪一步、成本是否合理、能否恢复 |
| Memory | 中期可深入的研究方向 | 记什么、何时检索、如何摘要、何时更新或遗忘 |
| Planning / Reasoning | 闭环稳定后再引入 | 是否需要显式规划、何时重新规划、如何验证计划有效 |
| Coding Agent | 可验证的应用方向 | 结合代码与测试验证修复、自纠错和环境交互 |
| Computer Use / Security | 进阶方向 | 环境操作、权限约束、提示注入与动作安全 |
| Multi-Agent | 有明确需求时引入 | 分工、通信、共享状态、协调和额外成本 |
| Agent Learning / RL | 后期研究方向 | 如何从轨迹与反馈中学习工具、记忆或规划策略 |
| 垂直应用 | 框架验证场景 | 检验核心能力能否复用到真实任务 |

原对话特别强调 Evaluation：只看最终答案不足以诊断 Agent。需要检查工具选择、参数、观察结果、失败恢复以及完整执行轨迹。

## 3. 分阶段学习与验收

### 阶段一：做出一个能完成任务的单 Agent

学习模型 API、结构化消息、工具 schema、流式输出和执行循环。可以阅读成熟实现帮助理解；Aier 的核心循环由自己实现。

最小闭环：用户输入 → 构建上下文 → 调用模型 → 执行工具 → 回填观察 → 继续调用 → 最终答案或明确停止。

验收：能够完成一次工具任务和一次多步工具任务；无工具、错误参数、未知工具、工具异常、达到步数上限都有可验证行为。

### 阶段二：把通用部分沉淀为 MiniAgent

形成清晰的 Model、Tool、Context、Agent 接口，让应用只需提供任务、提示与工具。理解为什么需要抽象，比复制一套目录结构更重要。

验收：至少两个不同任务场景复用同一执行循环，不修改核心代码即可替换工具；核心行为有离线回归测试。

### 阶段三：用应用检验框架

原对话建议的应用包括研究 Agent、股票研究 Agent 和 Coding Agent。Aier 可先从本地文件分析开始，再增加搜索与证据管理。

- 研究 Agent：检索 → 保存证据 → 分析 → 输出带引用的报告。
- 股票研究 Agent：围绕资料、市场数据和风险分析产出研究报告，以证据覆盖和引用正确性作为验收依据。
- Coding Agent：读取代码 → 修改 → 运行测试 → 根据失败信息继续修复。

验收：为每类任务定义可检查的结果，不以演示中的一两次成功代替稳定性验证。

### 阶段四：建立 Trace 与 Evaluation

先用少量固定任务建立基线，再扩展任务类别和难度。原对话的百任务评测集是长期设想，不是起步要求。

| 指标 | 作用 |
| --- | --- |
| 任务成功率 | 判断是否达到任务预先定义的完成条件 |
| 工具选择与参数正确率 | 区分模型决策、参数生成和工具执行问题 |
| 步数、token 用量、耗时 | 衡量执行效率；有用量和价格依据后才计算费用 |
| 重试次数、无效动作数 | 衡量恢复能力与无效循环 |
| 证据与引用正确性 | 检查研究类结果是否有可追溯依据 |

单元测试验证框架契约，任务评测验证 Agent 的实际效果，两者都需要。离线模拟适合回归，真实模型实验用于衡量实际任务表现。

### 阶段五：聚焦一个研究问题

可优先在 Memory 或 Evaluation / Reliability 中选一个问题。

**Memory 示例**：比较完整历史、滑动窗口、摘要和检索策略；固定任务、模型与预算，衡量成功率、成本、关键信息遗漏和检索错误。

**Reliability 示例**：向工具注入超时、错误结果或临时失败；比较直接终止、有限重试、模型自纠错与重新规划的效果。

验收：有明确问题、基线、可复现任务、实验变量、指标和失败案例分析。框架本身是实验载体，功能实现本身不等同于论文贡献。

### 阶段六：进阶能力与学习

再按实际问题引入更长任务、检查点、MCP、沙箱、Computer Use 或多 Agent。增加多 Agent 时，必须与单 Agent 基线比较收益和通信成本。

Agent Learning 的递进关系是：收集轨迹 → 定义反馈或奖励 → 构建数据 → 优化策略 → 在独立任务上评测。RL 需要模型训练或策略优化条件，不能仅靠增加反思提示实现。

## 4. Aier 在路线中的位置

截至整理时，Aier 的 `main` 已有模型工厂、OpenAI 格式适配、结构化消息与流式事件、工具基类与注册组件、滑动窗口短期记忆，以及代码检查与模型流回归测试。

尚未实现的关键能力：`ReactAgent` 执行循环、工具结果的完整协议回填、运行状态、轨迹持久化和任务级评测。长期记忆、技能加载、MCP、多 Agent 与任务恢复属于后续能力。

因此，Aier 适合作为从零学习与自写轻量框架的持续项目。目前的优先级应是**单 Agent 闭环 → 应用验证 → Trace / Eval → Memory / Reliability**。详细验收见 [技术路线图](ROADMAP.md)。

## 5. 项目集如何组织

| 项目或成果 | 作用 | 与 Aier 的关系 |
| --- | --- | --- |
| Agent-from-Scratch | 展示核心机制的学习过程 | 可以保留为 Aier 示例和开发记录，不必独立建仓库 |
| MiniAgent / Aier | 提供可复用的执行核心 | 长期维护的框架主项目 |
| Research / Stock Research Agent | 验证检索、证据和报告能力 | 消费 Aier 的核心接口 |
| Coding Agent | 验证环境交互和自纠错 | 使用 Aier，并在受控环境中操作代码 |
| AgentBench-lite | 比较策略和版本 | 评测 Aier 与其应用，可先放在同一仓库 |

框架、应用、评测与研究实验可以构成同一条成长轨迹。是否拆仓库取决于独立使用和维护需求，不需要为了项目数量重复实现核心循环。

## 6. 学习原则

- 先完成可验证的单 Agent，再研究复杂协作。
- 先建立基线和评测，再判断新机制是否有效。
- 先解决真实任务的问题，再增加抽象和模块。
- 保存消息是记忆的起点；摘要、检索与经验复用需要单独验证。
- 演示成功、框架正确和研究结论分别需要对应证据。
- 不把原对话中的目录、版本号或研究方向视为必须全部实现的清单。
