# aier.ai 与 aier.agent 的职责边界

- 更新日期：2026-10-05
- 用途：指导模块归属与后续接口设计；本文中的目标分层不代表所有功能已经实现。

## 1. 核心区别

**`aier.ai` 负责一次模型调用；`aier.agent` 负责通过多次模型调用与工具执行完成任务。**

一次模型调用可以是流式输出，也可以返回工具调用请求而不是最终答案。模型层将供应商协议转换成统一输入输出；Agent 层据此决定执行什么动作、构建下一轮上下文，以及何时停止。

判断功能归属时，先问：它只需要理解模型协议，还是需要理解任务执行过程？前者属于 `ai`，后者属于 `agent`。

## 2. 功能归属

| 功能 | 归属 | 职责 |
| --- | --- | --- |
| 模型接口、供应商适配、客户端配置 | `aier.ai` | 调用模型并屏蔽协议差异 |
| 消息、工具调用、工具结果、用量与结束原因类型 | `aier.ai` | 定义模型输入输出契约 |
| 消息序列化与工具 schema 转换 | `aier.ai` | 转换为供应商要求的请求格式 |
| 流式事件、工具参数分片组装 | `aier.ai` | 将供应商响应转换成统一事件与完整调用请求 |
| 结构化输出协议支持 | `aier.ai` | 提供单次模型输出格式约束 |
| Agent 循环、停止条件、最大步数 | `aier.agent` | 控制任务执行 |
| 工具注册、查找、参数校验与执行 | `aier.agent` | 将模型请求变成实际动作 |
| 工具超时、执行失败与恢复 | `aier.agent` | 决定失败后的处理方式 |
| 上下文选择、裁剪、摘要、记忆检索 | `aier.agent` | 决定下一次模型看到什么 |
| 短期记忆、长期记忆、经验管理 | `aier.agent` | 管理跨调用与跨任务的信息 |
| 规划、反思、技能加载 | `aier.agent` | 管理任务执行策略 |
| 任务状态、检查点、暂停与恢复 | `aier.agent` | 管理运行生命周期 |
| 运行轨迹、子 Agent 与协作 | `aier.agent` | 记录与协调完整执行过程 |

补充区分：供应商连接错误和 SDK 请求重试属于模型适配层；是否重新尝试一个任务步骤、重新规划或改用工具，属于 Agent 策略。SDK 的重试预算也需要纳入整次运行的资源限制。

模型用量由 `ai` 提供，跨调用的用量汇总与任务成本统计由 `agent` 完成。任务评测可作为独立的 `evals` 或测试模块消费运行轨迹，不需要把评测逻辑放进模型适配器。

## 3. Tool：模型看到描述，Agent 执行动作

```text
aier.agent：注册工具，提供名称、描述与参数定义
    ↓
aier.ai：转换供应商 schema，发送模型请求
    ↓
aier.ai：解析并返回 ToolCall(id, name, arguments)
    ↓
aier.agent：检查权限、查找工具、校验参数、执行函数
    ↓
aier.agent：生成工具结果消息，加入下一轮上下文
    ↓
aier.ai：转换消息格式，再次调用模型
```

`ai` 返回工具调用请求时不自动执行工具。是否允许执行、需要人工批准、失败后如何恢复，均由 `agent` 决定。

工具参数的 JSON 分片组装属于 `ai`；解析完整参数并按工具定义进行执行前校验属于 `agent`。工具结果的内部消息类型可以放在 `ai`，但产生该消息与选择是否继续执行属于 `agent`。

MCP 连接、工具发现与实际调用放在 Agent 工具接入层；`ai` 只接收转换后的模型可见定义，不需要依赖 MCP 的运行生命周期。

## 4. Context：定义容器与决定内容

`ai.Context` 包含系统提示、消息和工具定义，作为一次调用的输入容器放在 `ai` 合理。

`agent` 负责构建和更新这个容器，包括选择历史消息、注入检索记忆、处理长工具结果、加载技能与计划，以及按预算裁剪上下文。裁剪时需要保护工具调用和结果的配对关系。

`ai` 不自动改变历史、删除消息或注入记忆。保存一份 `Context` 也不等于实现记忆系统。

## 5. Memory：策略属于 Agent，模型可以参与计算

```text
agent 判断历史需要摘要
    → ai 调用模型生成摘要
    → agent 保存摘要并重建上下文
```

摘要、规划、反思与记忆提取都可能调用模型，但功能归属取决于谁负责决策和管理结果。模型参与计算，不意味着执行策略需要放入 `ai`。

长期存储、检索时机、信息遗忘与经验复用属于 `agent`；数据库或检索库是可替换的实现依赖。

## 6. 接口与依赖方向

目标接口职责：

```text
model.stream_invoke(context)：输入一次调用的上下文，返回模型事件。
agent.run(task)：输入任务，管理调用、工具执行、上下文与终止条件。
```

当前 `stream_invoke` 已实现；`BaseAgent.run` 仍是抽象接口，具体 Agent 循环尚未实现。上述说明不约束未来运行结果必须是纯字符串。

依赖方向是 `aier.agent → aier.ai → 供应商 SDK`。模型层可以独立用于聊天、生成与分类，不应导入 Agent、记忆或任务运行时。Agent 层依赖统一模型契约，避免直接操作供应商响应对象。

## 7. 当前代码与后续收敛

当前 `ai.Tool` 同时提供 `schema()` 与 `execute()`，`agent.ToolRegistry` 另维护 schema 与函数映射。这是现有实现的边界混合，不应将两条路径当成最终设计。

短期可保留 `ai.Tool` 作为共享契约，由 `agent` 调用 `execute()`，模型适配器只读取 schema。后续在工具接口收敛时，建议由 `agent` 管理可执行工具，向 `ai` 提供模型可见的定义。仅在实现闭环确有需要时拆分，避免为分层增加不必要的抽象。

后续修改可按以下问题检查：

- 新供应商是否只需增加模型适配，而无需改写 Agent 循环？
- 更换记忆或规划策略是否不影响模型协议转换？
- 工具执行是否由 Agent 控制，而非流式模型解析触发？
- 单次模型调用是否能在没有 Agent 运行时的情况下独立使用？
